# 연말정산 트래킹 — 설계

> 가계부의 부가기능이다. 가계부 기능이 기본이고, 연말정산 화면은 가계부 데이터를 읽어
> 채울 수 있는 칸은 자동으로 채운다. 나머지는 사람이 입력하거나 고치도록 **수정필요**로 남긴다.
> 결과는 **참고용 모의계산**이다. 화면에 항상 그렇게 표시한다.

## 목표

- 연말 한 번이 아니라 **연중 아무 때나** "지금 기준 예상 환급(추가납부)액" 을 본다.
- 연말정산 전체 흐름(총급여 → 소득공제 → 과세표준 → 세액공제 → 결정세액 → 환급)을
  하나의 체크리스트로 보여 준다. 칸마다 **값 · 출처 · 상태**를 붙인다.
- 비어 있거나 추정치인 칸이 몇 개 남았는지 보이고, 그것을 줄여 가는 것이 사용 흐름이다.

범위 밖: 신고 대행, 홈택스 제출, 사업·금융소득 종합과세, 맞벌이 최적 배분 계산.
지원 대상은 **근로소득만 있는 1인**이다. 이직한 해는 종전 근무지 금액을 수동 입력해서 처리한다.

## 1. 전체 워크플로우

연말정산 계산 순서를 그대로 화면 섹션으로 쓴다. 섹션 안 칸은 각각 상태 배지(2장)를 갖는다.

```
① 기본정보      귀속연도 · 부양가족 구성 · 자격 조건(무주택 세대주 등)
② 소득          총급여(비과세 제외) ─► 근로소득공제 ─► 근로소득금액
③ 소득공제      인적공제 · 연금보험료 · 건강/고용보험료 · 주택자금 · 주택청약 · 신용카드 등
                ─► 과세표준 ─► 산출세액(기본세율)
④ 세액감면·공제 근로소득세액공제 · 자녀 · 연금계좌 · 보험료 · 의료비 · 교육비 · 기부금
                (또는 표준세액공제) · 월세 · 결혼 …  ─► 결정세액(0 미만이면 0)
⑤ 기납부세액    현 근무지 원천징수 + 종전 근무지
⑥ 결과          차감징수세액 = 결정세액 − 기납부세액  (음수면 환급) + 지방소득세 10%
```

- 계산은 **항상 전체를 다시** 한다. 한 칸만 비어도 결과는 나오고, 그 칸은 0 으로 계산한 뒤
  결과 옆에 "수정필요 N개" 를 붙인다. 결과를 숨기지 않는다. 연중 트래킹은 원래 불완전한
  상태에서 보는 것이기 때문이다.
- 공제율 · 한도 · 세율 같은 숫자는 이 문서에 적지 않는다. 귀속연도별 규칙 파일
  (`lib/tax/rules/<연도>.mjs`)이 유일한 출처다. 국세청 연말정산 안내 기준으로 확정하고
  출처를 주석에 남긴다. 세법은 매년 바뀐다.

### 칸 목록과 채우는 방법

| 섹션 | 칸 | 가계부에서 | 기본 상태 |
| --- | --- | --- | --- |
| ① | 부양가족 인원 · 연령 구분 · 장애 · 한부모 등 | 없음 | 미입력 |
| ① | 자격 조건(무주택 세대주, 중소기업 취업자 감면 등) | 없음 | 미입력 |
| ② | 총급여 | `수입` 의 급여 입금은 **세후 실수령액**이라 쓸 수 없다. 입금 여부만 교차 확인용으로 보여 준다 | 미입력 |
| ③ | 국민연금 · 건강보험 · 고용보험 본인부담분 | 급여에서 원천공제되어 계좌에 안 보인다 | 미입력 |
| ③ | 주택청약종합저축 납입액 | 적요 `청약` 출금 → 후보 | 추정 → 태그하면 자동 |
| ③ | 주택임차차입금 원리금 · 장기주택저당차입금 이자 | `주거비` 의 대출 이자 항목 → 후보 금액. 대출 종류와 자격은 알 수 없다 | 추정 |
| ③ | 신용카드 등 사용액(신용 / 체크·현금영수증 / 전통시장 / 대중교통 / 문화 등) | `카드대금` 카드사별 결제액 → 신용카드 사용액 **추정**(4장) | 추정 |
| ④ | 연금계좌(연금저축 · IRP) 납입액 | `저축` 의 IRP · 연금 항목. ISA 는 세액공제 대상이 아니라 빼야 한다 | 추정 → 태그하면 자동 |
| ④ | 보장성 보험료 | `고정비` 자동이체 중 적요 `보험` → 후보. 보장성인지는 사람이 확인 | 추정 |
| ④ | 월세 | `주거비` 의 월세 항목 → 금액. 자격(무주택 세대주 · 총급여 기준)은 ① 에서 | 추정 → 태그하면 자동 |
| ④ | 기부금 | 적요 `기부` · `후원` 출금 → 후보 | 추정 |
| ④ | 의료비 · 교육비 | 대부분 카드로 내서 계좌에 안 보인다 | 미입력 |
| ④ | 자녀 · 결혼 등 인원/사건 기반 공제 | ① 에서 계산 | 자동(① 입력 후) |
| ⑤ | 기납부세액(현 · 종전 근무지) | 없음. 급여명세서의 소득세 누계 | 미입력 |

"후보" 는 적요 패턴으로 찾은 것이다. 사람이 그 항목을 세무 칸에 **태그**하면(3장) 그 뒤로는 자동이다.

## 2. 칸의 상태

| 상태 | 뜻 | 수정필요? |
| --- | --- | --- |
| **자동** | 가계부 항목을 사람이 태그했고, 그 거래 합계로 채웠다 | 아니오 |
| **추정** | 가계부에서 근사했다(패턴 후보, 카드대금 기반 추정, 연말 예상치) | **예** |
| **수동** | 사람이 입력했다 | 아니오 |
| **조정** | 자동 · 추정 값을 사람이 덮어썼다(사유는 선택) | 아니오 |
| **해당없음** | 사람이 "해당 없음" 으로 닫았다(값 0) | 아니오 |
| **미입력** | 아무 값도 없다(0 으로 계산) | **예** |

- 값을 고르는 우선순위: **조정 · 수동 · 해당없음 > 자동 > 추정 > 미입력.** 가계부의
  `manual > map > rule` 원칙과 같다. 사람이 고른 값을 자동 채우기가 덮지 않는다.
- 자동 값은 **저장하지 않는다.** 요청마다 거래에서 다시 계산한다. 그래서 거래를 다시
  분류하면 연말정산 칸이 따라 바뀐다. 저장하는 것은 사람이 입력한 값과 태그뿐이다.
- 결과 화면의 "수정필요" 목록은 추정 · 미입력 칸이다. 결과에 미치는 영향이 큰 칸
  (총급여 · 기납부세액 · 카드)을 먼저 보여 준다.

## 3. 가계부 → 연말정산 연결: 항목 태그

가계부는 이미 **(분류, 항목)** 단위로 거래를 묶는다(`저축 → IRP`, `주거비 → 월세` …,
`lib/classify/item.mjs`). 연말정산 칸은 이 묶음을 그대로 받는다.

- `tax_item_tags` (분류, 항목) → 세무 칸. `merchant_map` 처럼 한 번 고르면 계속 적용된다.
- 태그가 없는 묶음은 적요 패턴 후보(1장 표)로 **추정** 칸에 제안만 한다. 화면에서
  "이 항목을 연금계좌로 인정" 을 누르면 태그가 생기고 상태가 자동이 된다.
- 금액은 귀속연도(KST 거래일 기준, `year_month` 의 연도) 출금 합계다. 환불이나 해지로
  들어온 입금은 같은 항목에서 뺀다.
- **가계부 데이터가 없는 달**은 자동 칸이 그 달을 0 으로 세지 않도록, 칸 옆에
  "거래내역이 있는 달: 3월~10월" 처럼 범위를 표시하고 상태를 추정으로 내린다.
  가계부 시작 이전 달(PLAN.md 미결: 과거 데이터 이관)이 여기에 해당한다.

## 4. 카드 소득공제

가장 큰 구멍이다. 공제는 **사용일** 기준이고 결제수단별(신용 / 체크·현금 / 전통시장 /
대중교통 …)로 공제율이 다르며, 총급여 대비 문턱을 넘은 금액부터 공제된다. 가계부에는
**카드사별 월 결제대금**만 있다(건별 내역은 저장하지 않는다는 원칙, PLAN.md).

1. **기본값(추정):** 카드대금 결제액을 한 달 앞당겨 "그 달 신용카드 사용액" 으로 본다.
   전부 신용카드라는 PLAN.md 의 전제와 맞는다. 상태는 항상 추정이다.
2. **입력(수동 · 조정):** 카드사 앱이나 홈택스(11월 연말정산 미리보기)에 나오는
   **월별 · 결제수단별 합계**를 입력한다. 건별 내역은 받지 않는다.
3. 트래커: 문턱(총급여 × 규칙 파일의 비율)까지 남은 금액, 문턱을 넘은 뒤 결제수단별
   추가 공제 효과를 보여 준다("이제부터는 체크카드가 유리").

## 5. 연중 트래킹 — 현재까지 vs 연말 예상

모든 금액 칸은 두 값을 갖는다.

- **현재까지:** 오늘까지의 거래와 입력값.
- **연말 예상:** 남은 달을 채운 값. 항상 추정 상태다.
  - 총급여: 연봉을 입력했으면 그 값을 쓰고, 아니면 월 금액 × 12
  - 반복 납입(IRP 자동이체, 월세, 청약): 최근 달 금액 × 남은 달
  - 카드: 최근 3개월 평균 × 남은 달
  - 기납부세액: 월 원천징수액 × 남은 달

결과 카드는 연말 예상 기준 환급액을 크게 보여 주고, 현재까지 기준 값을 작게 함께 보여 준다.

**만약 계산(what-if):** 결과 화면에서 한 칸만 바꿔 다시 계산한다. 저장하지 않는다.
예: "연금계좌에 X원 더 넣으면", "남은 카드 사용을 체크카드로 바꾸면".
결정세액이 이미 0 이면 "추가 공제 효과 없음" 을 먼저 알려 준다.

## 6. 데이터와 보안

새로 들어오는 민감정보는 **총급여 · 세액 · 가족 구성**이다. PLAN.md 보안 체계를 그대로 따르고,
여기서 더 줄인다.

- **저장하지 않는다:** 주민등록번호, 가족 이름 · 생년월일(연령 **구분별 인원**만 받는다),
  의료기관 · 학교 · 기부처 이름, 급여명세서 · 홈택스 PDF 원본.
- 장애 여부 같은 건강 관련 정보도 **인원 수**로만 받는다.
- 입력값 메모는 짧게(길이 상한) 두고, 어떤 로그 · 에러 응답에도 싣지 않는다. 쓰기 API 는
  받은 금액이나 메모를 되비추지 않는다(`/api/classify*` 와 같은 규칙).
- 화면은 서버 컴포넌트, `force-dynamic`, 요청마다 세션 + `ALLOWED_EMAILS` 확인.

스키마 초안(확정은 해당 PR 에서):

```
tax_entries    (tax_year, field_key, period NULL, amount NULL, count NULL, flag NULL,
                status 'manual' | 'override' | 'na', note NULL, updated_at)
               ─ 사람이 입력한 값만. field_key 는 코드의 칸 목록(lib/tax/fields.mjs)으로 검증
               ─ period 는 월별 입력이 필요한 칸(카드 결제수단별, 원천징수)에만 'YYYY-MM'
tax_item_tags  (category, item) PK → tax_field, updated_at
               ─ 가계부 묶음을 세무 칸에 연결. 금액은 저장하지 않는다
```

## 7. 구현 단계 (PR 단위)

| 단계 | 내용 | DB | 사용자가 얻는 것 |
| --- | --- | --- | --- |
| **T1** | `lib/tax/` 계산 엔진: 칸 목록(`fields.mjs`) · 규칙(`rules/2026.mjs`) · `compute()` 순수 함수(칸 값 + 상태 → 단계별 결과 + 수정필요 목록). 국세청 계산 예시로 테스트 | 없음 | (내부) |
| **T2** | `tax_entries` 마이그레이션 + `/tax` 화면: 섹션별 체크리스트, 수동 입력 · 해당없음, 결과 카드 | 추가 | **수동 입력만으로 모의정산 가능** |
| **T3** | 가계부 자동 채우기 + `tax_item_tags`: 연금계좌 · 월세 · 청약 · 주택대출 이자 · 보험료 · 기부금 후보, 상태 배지, 거래내역 있는 달 범위 표시 | 추가 | 자동 칸이 채워짐 |
| **T4** | 카드: 결제대금 기반 추정 + 월별 · 결제수단별 입력 + 문턱 트래커 | 없음(T2 테이블 사용) | 카드 공제 추적 |
| **T5** | 연말 예상 · 만약 계산 | 없음 | 연중 트래킹 |
| T6 (선택) | 홈택스 PDF(11월 미리보기 · 1월 간소화) 업로드로 수동 칸 일괄 채우기 — 의존성 없는 PDF 파싱이 어려워 따로 결정 | 없음 | 1월 입력 수고 감소 |

T2 가 끝나면 수동 입력만으로도 쓸 수 있다. T3 부터는 입력 부담이 줄어든다.
첫 대상 귀속연도는 **2026**(2027년 1월 정산분)이다.

## 8. 미결

- **카드 입력 단위** — 월별(제안) vs 분기 · 누적. 카드사 앱에서 보이는 단위를 따른다.
- **연봉 입력 방식** — 연봉 한 번 입력(제안) vs 급여명세서 월별 입력. 월별이면 원천징수
  세액도 같이 받아서 ⑤ 를 정확하게 채울 수 있다.
- **T6 PDF 업로드** — 필요성은 2027년 1월 실제 정산 때 판단한다.
- **2025 귀속 소급** — 지원하지 않는다(제안). 이미 끝난 정산이다.
