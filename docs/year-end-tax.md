# 연말정산 공제 트래커 — 설계

> 가계부의 부가기능이다. **이 앱으로 연말정산을 하지 않는다.** 가계부 거래로 확인되는
> 공제 항목만 골라, 1년 동안 얼마나 쌓였는지와 한도 대비 남은 금액, 대략의 공제 효과를 보여 준다.
> 결과는 **참고용 추정**이다. 화면에 항상 그렇게 표시한다.
>
> 연말정산 전체(뜻 · 일정 · 계산 방법)는 [연말정산 가이드](year-end-tax-guide.md)에 있다.
> 앱의 가이드 탭 원문이다.

## 목표

- 연중 아무 때나 "IRP 연 한도 중 얼마를 채웠고, 남은 한도를 채우면 세금이 얼마 줄어드는지" 를 본다.
- 사람이 넣는 값은 **연봉, 한계세율, 자격 체크 몇 개**로 끝낸다. 나머지는 가계부 거래에서 온다.
- 가계부에서 공제 후보를 찾아 주고, 사람이 한 번 "공제 항목이 맞다" 고 연결하면 그 뒤로는 자동이다.

**범위 밖**: 환급(추가납부)액 계산. 그러려면 총급여 · 기납부세액 · 4대보험 · 부양가족 ·
의료비 · 교육비를 모두 입력해야 해서 사실상 연말정산을 다시 하게 된다. 필요해지면 나중에
선택 기능으로 검토한다(가이드 3~4장이 계산 구조다).

## 1. 추적하는 항목

가계부는 토스뱅크 계좌 거래만 본다. 그래서 **계좌에서 돈이 나가는 공제 항목**만 다룬다.

### 자동 — 한 번 연결하면 계속 채워진다

| 항목 | 공제 종류 | 가계부에서 | 사람이 할 일 |
| --- | --- | --- | --- |
| 연금저축 | 세액공제 | `저축` 의 연금저축 항목 | 항목을 "연금저축" 으로 연결 |
| IRP | 세액공제 | `저축` 의 IRP 항목 | 항목을 "IRP" 로 연결. ISA 는 공제 대상이 아니다 |
| 주택청약종합저축 | 소득공제 | 적요 `청약` 출금 | 연결 + 무주택 세대주 체크 |
| 월세 | 세액공제 | `주거비` 의 월세 항목 | 연결 + 무주택 세대주 체크 |

### 반자동 — 금액은 가계부에서, 공제 대상인지는 사람이 판단

| 항목 | 공제 종류 | 가계부에서 | 사람이 판단할 것 |
| --- | --- | --- | --- |
| 주택임차차입금 원리금 | 소득공제 | `주거비` 의 대출 이자(원금 상환이 계좌에 보이면 그것도) | 전세자금대출인지 |
| 장기주택저당차입금 이자 | 소득공제 | `주거비` 의 대출 이자 | 주택담보대출인지, 한도 구간(상환 기간 · 방식) |
| 보장성 보험료 | 세액공제 | `고정비` 자동이체 중 적요 `보험` | 보장성 보험인지 |
| 기부금 | 세액공제 | 적요 `기부` · `후원` 출금 | 일반 / 정치자금 / 고향사랑 중 무엇인지 |
| 신용카드 등 사용액 | 소득공제 | `카드대금` 카드사별 결제액 | **추정치**다(3장). 확인한 금액으로 보정할 수 있다 |

### 다루지 않는 것

총급여 · 4대보험 · 기납부세액(계좌에는 세후 실수령액만 보인다), 부양가족 · 자녀 · 출산 · 혼인 ·
중소기업 감면(사람 · 사건 기반), 의료비 · 교육비(주로 카드 결제라 계좌에 안 보인다),
근로소득공제 · 세율(계산 규칙).

## 2. 항목 연결과 상태

가계부는 이미 **(분류, 항목)** 으로 거래를 묶는다(`저축 → IRP`, `주거비 → 월세` …,
`lib/classify/item.mjs`). 트래커는 이 묶음을 공제 항목에 연결한다.

- `tax_item_tags` (분류, 항목) → 공제 항목. `merchant_map` 처럼 한 번 고르면 계속 적용된다.
  "공제 항목 아님" 도 연결의 한 종류로 저장해서 같은 후보를 다시 묻지 않는다.
- 연결이 없고 1장 표의 패턴에 걸리는 묶음은 **후보**로 보여 준다. 후보 금액은 합계에 넣지 않는다.

| 상태 | 뜻 | 합계에 넣나 |
| --- | --- | --- |
| **연결됨** | 사람이 공제 항목으로 연결했다 | 예 |
| **후보** | 패턴에 걸렸지만 아직 연결하지 않았다. "연결 / 아님" 버튼 | 아니오 |
| **자격 확인 필요** | 연결됐지만 필요한 자격 체크(무주택 세대주 등)가 비어 있다. 금액은 보이고 효과는 계산하지 않는다 | 금액만 |
| **추정** | 카드처럼 가계부에서 근사한 값 | 예(표시 붙음) |

- 금액은 귀속연도(KST 거래일 기준, `year_month` 의 연도)의 출금 합계다. 같은 항목으로 들어온
  환불 · 해지 입금은 뺀다.
- 금액은 **저장하지 않는다.** 요청마다 거래에서 다시 계산한다. 거래를 다시 분류하면 트래커가 따라 바뀐다.
- **가계부 데이터가 없는 달**이 있으면 "거래내역이 있는 달: 3월~10월" 처럼 범위를 같이 보여 준다.
  가계부 시작 이전 달(PLAN.md 미결: 과거 데이터 이관)은 0 으로 보이는 것이 아니라 비어 있는 것이다.

## 3. 화면에 보여 주는 것

항목마다 한 줄이다.

```
IRP                         연결됨
  올해 납입      300만원    ████░░░░░░  한도 900만원(연금저축 합산)
  공제 효과      약 49.5만원 (세액공제 15% + 지방소득세)
  남은 한도      600만원 → 채우면 약 +99만원
```

- **공제 대상 금액** = min(누적 금액, 한도). 합산 한도(연금저축 + IRP, 청약 + 주택임차차입금 …)는
  엔진이 처리한다.
- **공제 효과**
  - 세액공제: 공제 대상 금액 × 공제율 × 1.1(지방소득세)
  - 소득공제: 공제액 × **한계세율** × 1.1. 한계세율은 **사용자가 고른다**(6 · 15 · 24 · 35 · 38 · 40 ·
    42 · 45%). 연봉으로 추정하지 않는다(사용자 결정 2026-11 — 추정은 구간 경계에서 크게 틀린다).
    고르는 법: 작년 근로소득 원천징수영수증의 "과세표준" 을 세율표에서 찾는다. 고르기 전까지 소득공제
    항목은 공제액만 보여 주고 효과는 "한계세율 선택 필요" 로 둔다
  - 연봉은 공제율 · 자격 구간을 가르는 데 쓴다: 연금계좌(5,500만), 월세(5,500만 · 8,000만), 주택청약
    (7,000만 이하), 카드 문턱(25%) · 한도(7,000만)
- **효과는 낼 세금이 충분할 때의 최대치**다. 결정세액이 이미 0 이면 효과가 없다. 트래커는 결정세액을
  계산하지 않으므로 이 문장을 결과 옆에 항상 둔다.
- 상단 요약: 연결된 항목들의 공제 효과 합계(추정), 후보 · 자격 확인 필요 개수.

### 신용카드 등 사용액 (추정)

공제는 **사용일** 기준이고 결제수단별 공제율이 다르며 총급여 25% 문턱을 넘은 금액부터 공제된다.
가계부에는 **카드사별 월 결제대금**만 있다(건별 내역은 저장하지 않는다는 원칙, PLAN.md).

1. **추정**: 결제대금을 한 달 앞당겨 그 달 신용카드 사용액으로 본다. 전부 신용카드라는 PLAN.md 의
   전제와 맞는다. 관리비처럼 공제되지 않는 결제가 섞여 있어 실제보다 크게 나올 수 있다.
2. **보정**: 홈택스 연말정산 미리보기(11월, 1~9월분)나 카드사 앱에서 확인한 누계를 입력하면
   그 달까지는 확인값을 쓴다.
3. **보여 주는 것**: 25% 문턱까지 남은 금액, 문턱을 넘었으면 추정 공제액과 "이제부터는 체크카드 ·
   현금영수증이 유리" 안내.

## 4. 데이터와 보안

새로 저장하는 값은 **연봉, 한계세율, 자격 체크 몇 개, 항목 연결**뿐이다. 이전 설계(전체 연말정산)와 달리
부양가족 · 세액 · 기관명은 받지 않는다. PLAN.md 보안 체계를 그대로 따른다.

- 연봉은 로그 · 에러 응답 · API 응답 본문에 싣지 않는다. 쓰기 API 는 받은 값을 되비추지 않는다
  (`/api/classify*` 와 같은 규칙).
- 화면은 서버 컴포넌트, `force-dynamic`, 요청마다 세션 + `ALLOWED_EMAILS` 확인. middleware 로그인 관문 뒤.

스키마 초안(확정은 해당 PR 에서):

```
tax_year_settings (tax_year PK, annual_salary NULL, marginal_rate NULL, homeless_householder NULL,
                   mortgage_limit_tier NULL, card_confirmed_amount NULL,
                   card_confirmed_through NULL 'YYYY-MM', updated_at)
                  ─ 귀속연도마다 한 행. 비어 있는 칸은 "미입력" 으로 보여 준다
tax_item_tags     (category, item) PK → deduction 'pension_savings' | 'irp' | 'housing_subscription'
                   | 'rent' | 'lease_loan' | 'mortgage_interest' | 'insurance'
                   | 'donation_general' | 'donation_political' | 'donation_hometown' | 'none', updated_at
                  ─ 가계부 묶음을 공제 항목에 연결. 금액은 저장하지 않는다
```

## 5. 숫자의 출처

- 공제율 · 한도 · 세율은 이 문서에 적지 않는다. 귀속연도별 규칙 파일(`lib/tax/rules/<연도>.mjs`)이
  계산 기준이다. 국세청 연말정산 안내 기준으로 확정하고 출처를 주석에 남긴다. 세법은 매년 바뀐다.
- 가이드의 숫자와 규칙 파일은 같아야 한다. 한쪽을 고치면 같은 PR 에서 다른 쪽도 고친다.
- 트래커가 쓰는 규칙은 가이드의 일부다: 기본세율 구간(한계세율 선택지), 1장 항목들의
  공제율 · 한도, 카드 문턱 · 공제율 · 한도, 소득공제 종합한도.
- ⚠️ 2026년 귀속 개정이 보도되었지만 확인 전인 항목은 확정 전까지 **현행 값**을 쓴다(사용자 결정 2026-11).

## 6. 구현 단계 (PR 단위)

| 단계 | 내용 | DB | 사용자가 얻는 것 |
| --- | --- | --- | --- |
| **T0** | 이 설계 + [연말정산 가이드](year-end-tax-guide.md) | 없음 | (문서) |
| **TG** | **가이드 탭**(`/tax/guide`): 가이드 문서를 앱에서 보여 준다. 정적 내용이라 T1 과 순서를 바꿔도 된다 | 없음 | 앱에서 가이드 읽기 |
| **T1** | `lib/tax/` 공제 엔진(`deductions.mjs`): 규칙(`rules/2026.mjs`), 항목별 공제 대상 금액 · 합산 한도 · 효과 · 남은 한도, 카드 결제수단별 계산(가계부 추정치는 전부 신용카드). 한계세율은 입력. 순수 함수 + 테스트 | 없음 | (내부) |
| **T2** | 트래커 화면(`/tax`) + `tax_year_settings` · `tax_item_tags` 마이그레이션: 연봉 · 한계세율 · 자격 입력, 자동 · 반자동 항목 집계, 후보 연결 / 아님 | 추가 | **공제 트래커 사용 가능** |
| **T3** | 카드: 결제대금 기반 추정, 25% 문턱 진행률, 확인값 보정 | 없음(T2 테이블 사용) | 카드 문턱 추적 |
| T4 (선택) | 연말 예상(정기 납입은 최근 달 × 남은 달), 리포트 화면 요약 카드 | 없음 | 연말 기준 예상 |

첫 대상 귀속연도는 **2026**(2027년 1월 정산분)이다.

**TG 결정(2026-11)**: 가이드는 `docs/year-end-tax-guide.md` 하나가 원문이다. 의존성 없는 변환기
(`lib/markdown/blocks.mjs`)가 블록 트리로 바꾸고 React 가 그린다(HTML 문자열을 만들지 않는다).
사용자 데이터가 없어 빌드 때 정적으로 굽고, 로그인 관문은 middleware 가 맡는다. 탭은 "연말정산" 하나에 트래커(`/tax`)와
가이드(`/tax/guide`)를 하위 탭으로 둔다.

## 7. 미결

- **카드 보정 입력** — 기준월까지 누계 한 값(제안) vs 월별 입력.
- **가이드의 ⚠️ 항목** — 국세청 「2026년 귀속 연말정산 신고안내」(2027년 1월)로 확인하고 지운다.
  T1 규칙 파일도 같은 자료로 확정한다.
- **2025 귀속 소급** — 지원하지 않는다. 이미 끝난 정산이다.
